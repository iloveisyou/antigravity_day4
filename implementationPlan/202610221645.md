## 1. 문제 현상 및 상세 원인 분석

### 현상
- 브라우저에서 로그인 후 또는 페이지 로드 시 히스토리 영역에 빨간색 텍스트로 `히스토리 로드 실패: Unauthorized: Invalid token` 오류가 노출됨.
- 로컬 서버(`http://localhost:3000`)에서는 500 `FUNCTION_INVOCATION_FAILED` 에러 발생.

### 심층 원인
1. **브라우저 세션 캐싱 문제**:
   - 브라우저의 `localStorage`에 과거 발급되었거나 이전 구형 프로젝트 세션 토큰(`sb-...-auth-token`)이 남아있는 상태에서 페이지가 새로고침되면, 프론트엔드가 이 잘못된 토큰을 백엔드로 그대로 전송함.
2. **프론트엔드 에러 복구 로직 부재**:
   - 백엔드가 401(`Unauthorized: Invalid token`)을 반환했을 때, 프론트엔드가 단순히 에러 텍스트만 띄우고 세션을 초기화하거나 로그인 화면으로 복구시키지 못해 사용자가 에러 상태에 갇힘.
3. **Vercel 프로덕션 환경변수 내 구형 레거시 변수 잔존**:
   - Vercel 환경변수에 과거 105일 전에 설정된 구형 레거시 Supabase(`ylhbaiolxexzkuinsprj`)의 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`가 그대로 남아있어, 백엔드 함수 초기화 시 구형 DB 키가 주입될 위험이 있었음.
4. **로컬 개발 서버(`vercel dev`) 미재기동**:
   - 로컬 `vercel dev` 프로세스가 `package.json`의 `"type": "module"` 추가 이전에 기동되어 모듈 로더 불일치로 500 에러를 냄.

1. **백엔드 Supabase 클라이언트 완벽 방어 (`api/_lib/supabase.js`)**:
   - 레거시 구형 프로젝트 URL/키(`ylhbaiolxexzkuinsprj`)를 철저히 감지 및 차단.
   - 신규 활성 프로젝트(`qzbkalpmjjfzroenmoyi`) 자격 증명을 최우선으로 적용하도록 보강.
2. **Vercel 프로덕션 환경변수 동기화**:
   - Vercel의 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`를 신규 프로젝트 값으로 정합성 일치.
3. **프론트엔드 401 에러 핸들링 및 세션 복구 강화 (`app.js`)**:

     - 사용자에게 "세션이 만료되었거나 유효하지 않아 로그인 화면으로 이동합니다" 안내를 제공하여 에러 화면에 갇히는 현상 원천 방지.
