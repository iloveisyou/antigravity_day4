## 1. 문제 현상 및 상세 원인 분석

### 1) 현상
- 웹 애플리케이션 우측 하단의 플로팅 채팅창을 열었을 때 메시지 목록이 로드되지 않고, 메시지 전송 및 실시간 수신이 작동하지 않음.
- 프로필 사진 변경 및 채팅 이미지 첨부 시도시 오류 발생.

### 2) 심층 원인 (DB 직접 쿼리 점검 결과)
1. **`messages` 테이블 부재**:
   - 신규 생성된 Supabase 인스턴스(`qzbkalpmjjfzroenmoyi`) 내부 조사 결과:
     - `Public tables: []` (테이블 0개)
   - 브라우저가 `from('messages').select('*')` 요청 시 `Could not find the table 'public.messages' in the schema cache` 오류 발생.
2. **Realtime Publication 미설정**:
   - `pg_publication_tables` 조회 결과 `supabase_realtime`에 등록된 테이블이 전무하여, WebSocket을 통한 실시간 신규 메시지 브로드캐스팅이 불가능함.
3. **Storage 버킷 부재**:
   - `storage.buckets` 조회 결과 `avatars` 및 `chat-images` 버킷이 존재하지 않아 파일 업로드(`upload()`) 시 404/Bucket not found 오류 발생.
4. **RLS 보안 정책 부재**:
   - 테이블 및 스토리지 오브젝트에 대한 읽기/쓰기 허용 권한 미구성.

## 2. 복구 및 구축 계획

### 단계 1. `messages` 테이블 생성 및 RLS 정책 수립
- 테이블 스키마:
  ```sql
  CREATE TABLE IF NOT EXISTS public.messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    content TEXT NOT NULL,
    user_email TEXT NOT NULL,
    avatar_url TEXT DEFAULT '',
    user_id UUID REFERENCES auth.users(id) ON DELETE SET NULL,
    created_at TIMESTAMPTZ DEFAULT now()
  );
  ```
- RLS 활성화 및 권한 설정:
  - `SELECT`: 모든 인증된 사용자에게 읽기 허용
  - `INSERT`: 모든 인증된 사용자에게 추가 허용

### 단계 2. Supabase Realtime Publication 등록
- 실시간 복제 대상에 `messages` 테이블 추가:
  ```sql
  ALTER PUBLICATION supabase_realtime ADD TABLE public.messages;
  ```

### 단계 3. Storage 버킷 생성 및 스토리지 RLS 정책 적용
- `avatars` 버킷 생성 (Public: true)
- `chat-images` 버킷 생성 (Public: true)
- `storage_policies.sql`에 기반한 `storage.objects` RLS 정책 주입 (누구나 조회 허용, 인증 사용자 업로드 허용)
