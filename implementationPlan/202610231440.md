## 1. 문제 현상 및 상세 원인 분석

### 현상
- 로컬 서버(`http://localhost:3000`)에서 정상 계정(`user@mindflow.com`)으로 로그인하면, 잠시 일기 화면이 보이는 듯하다가 **즉시 로그인 화면으로 다시 튕겨나가는 현상** 발생.

### 원인 체인 (Root Cause Chain)
1. **`.env` 파일 내 구형 프로젝트 키 잔존**:
   - `.env` 파일에 소멸된 구형 Supabase(`ylhbaiolxexzkuinsprj`)의 키가 그대로 남아있었음.
2. **`api/_lib/supabase.js` 키 필터링 결함**:
   - 기존 코드는 `!key.includes('ylhbaiolxexzkuinsprj')`로 구형 키를 걸러내려 했으나, JWT 토큰 특성상 payload가 Base64로 인코딩되어 있어 평문 `'ylhbaiolxexzkuinsprj'`가 포함되지 않음 (`InlsaGJhaW9seGV4emt1aW5zcHJq`로 인코딩됨).
   - 따라서 구형 키가 필터링을 뚫고 통과하여 신규 URL(`qzbkalpmjjfzroenmoyi`)과 구형 키가 조합됨.
3. **백엔드 토큰 검증 실패 (`401 Invalid API key`)**:
   - URL과 키의 ref가 불일치하여 `/api/history` 호출 시 Supabase가 `{"error":"Unauthorized: Invalid token","details":"Invalid API key"}` (HTTP 401)을 응답.
4. **프론트엔드의 즉시 강제 로그아웃 로직**:
   - `app.js`의 `fetchHistory()`는 401을 받으면 즉시 `window.supabaseClient.auth.signOut()`을 호출하고 `updateAuthUI(null)`로 로그인 폼으로 전환하도록 되어 있었음.
   - 이로 인해 로그인 직후 `fetchHistory()`가 실행되면서 401을 받아 **1초 만에 강제로 로그아웃되고 로그인 폼으로 튕겨나간 것**임.
5. **어제 기동된 구형 프로세스(PID 10572) 미재시작**:
   - 어제 4:25PM에 켜진 `vercel dev`가 종료되지 않고 계속 떠 있어 변경 사항이 로컬 서버에 반영되지 않았음.

## 2. 해결 방안

1. **`.env` 및 `.env.example` 동기화**:
   - 로컬 `.env`에 남아있던 구형 URL과 키를 신규 Supabase(`qzbkalpmjjfzroenmoyi`) 및 신규 Redis로 전면 교체.
2. **`api/_lib/supabase.js` JWT ref 검증 강화**:
   - 키를 단순 평문 검색이 아닌, JWT payload를 안전하게 파싱하여 `ref === 'qzbkalpmjjfzroenmoyi'`인 키만 통과시키도록 완벽 방어.
3. **프론트엔드(`app.js`) 401 예외 처리 개선**:
   - 401 에러 중 `details`가 `Invalid API key` 등 서버 설정 오류인 경우, 사용자의 세션을 강제 파기하지 않고 서버 오류 안내를 띄워 무한 튕김 방지.
4. **로컬 개발 서버 재시작 및 API 통신 검증**:
   - 구형 프로세스를 종료하고 새 설정으로 로컬 서버를 가동하여 로그인 후 정상 유지 및 히스토리 200 OK 확인.
