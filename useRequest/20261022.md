## 1. 배경: 오랜만에 접속했는데 왜 아무것도 안 됐을까?

이 프로젝트는 클라우드 무료 티어 서비스(Supabase, Upstash Redis, Vercel)를 기반으로 구축되어 있습니다.
- **Supabase 무료 티어 정책**: 프로젝트에 일정 기간(보통 7일~30일) API 호출이나 접근이 없으면 **자동 일시중지(Inactivity Pause)** 또는 장기 미사용 시 인스턴스가 삭제됩니다.
- **기존 인스턴스 소멸**: 기존에 연결되어 있던 Supabase(`ylhbaiolxexzkuinsprj`)와 Redis(`twinkling-helpful-top-24270`)가 완전히 만료/삭제되어 DNS 조회조차 되지 않는 상태(`NXDOMAIN`, `ENOTFOUND`)였습니다.
- **결과**: 서버 주소 자체가 인터넷상에서 사라졌기 때문에 로그인, 회원가입, 일기 저장, 히스토리 조회 등 모든 네트워크 요청이 일제히 불통 상태가 되었습니다.

## 2. 발생한 문제들과 단계별 해결 내역

### 문제 1. 기존 DB 및 Redis 소멸 (NXDOMAIN / ENOTFOUND)
- **증상**: 프론트엔드에서 로그인 시도시 콘솔에 네트워크 에러(`Failed to fetch`, `NXDOMAIN`) 발생.
- **원인**: 과거 Supabase 및 Redis 인스턴스가 장기 미사용으로 소멸됨.
- **해결 조치**:
  1. Vercel Storage 및 Supabase 대시보드에서 새로 프로비저닝된 신규 인스턴스 확인.
     - 신규 Supabase: `qzbkalpmjjfzroenmoyi.supabase.co`
     - 신규 Redis: `pigs-hospitable-rock-33934.db.redis.io`
  2. 프론트엔드 클라이언트(`supabase.js`) 주소를 신규 Supabase 프로젝트 URL 및 새 anon key로 교체.
  3. 로컬 환경 설정 파일(`.env.local`, `.env.development.local`)에 새 Redis URL 및 새 Supabase 키 동기화.

---

### 문제 2. 로그인 실패 ("Invalid login credentials")
- **증상**: 새 주소로 연결 후 기존 아이디/비번으로 로그인을 시도했으나 `Invalid login credentials` (로그인 정보 불일치) 팝업 발생.
- **원인**:
  - 새로 연동된 Supabase는 **완전히 백지 상태의 새 데이터베이스**였습니다.
  - 기존 인스턴스가 사라지면서 과거에 가입했던 유저 계정 데이터도 함께 사라졌으므로, 새 DB에는 등록된 유저가 0명이었던 상태였습니다.

---

### 문제 3. 회원가입 실패 ("429 over_email_send_rate_limit")
- **증상**: 유저가 없으니 '회원가입' 버튼을 눌러 새로 가입하려 했으나 `회원가입 실패: over_email_send_rate_limit` 에러 발생.
- **원인**:
  - Supabase 무료 티어에 기본 내장된 이메일 발송 서버는 스팸 방지를 위해 **시간당 3~4건**으로 발송 제한이 극도로 엄격합니다.
  - 가입 인증 메일 발송 한도를 즉시 초과하여 회원가입이 막힘.
- **해결 조치**:
  - Supabase 관리자 권한(Service Role Key)을 사용해 이메일 발송 과정을 건너뛰고, 이미 이메일 인증이 완료(`email_confirm: true`)된 **공식 개발 테스트 계정**을 스크립트로 직접 생성함:
    - **이메일**: `user@mindflow.com`
    - **비밀번호**: `Password123!`

### 문제 4. Vercel 배포 시 서버리스 빌드 실패 (Node 24 & ESM 충돌)
- **증상**: 코드를 푸시했으나 Vercel 빌드에서 에러 발생 (`Error [ERR_REQUIRE_ESM]: require() of ES Module`).
- **원인**:
  - Vercel의 서버리스 런타임이 최신 Node.js 24로 실행되면서, 백엔드 함수(`api/history.js`, `api/analyze.js`)가 CommonJS(`require`)와 ES Module(`import`) 혼용을 엄격히 차단함.
- **해결 조치**:
  1. `package.json`에 `"type": "module"` 명시.
  2. 백엔드 코드의 `require` 구문을 최신 표준 `import` 구문으로 전면 리팩토링.

---

### 문제 5. 히스토리 로드 실패 ("Unauthorized: Invalid token" & "unrecognized JWT kid")
- **증상**: 새 계정으로 로그인은 성공했으나, 하단 일기 내역 영역에 빨간색으로 `히스토리 로드 실패: Unauthorized: Invalid token` 오류 노출.
- **원인**:
  - Vercel 프로덕션 환경변수 목록에 신규 변수 외에도 **105일 전에 등록되었던 옛날 죽은 DB 정보(`ylhbaiolxexzkuinsprj`)**가 우선순위로 남아있었습니다.
  - 프론트엔드는 **신규 DB**에서 토큰을 받아 백엔드로 보냈는데, 백엔드는 Vercel 환경변수 우선순위 때문에 **옛날 죽은 DB**에 "이 토큰 유효해?"라고 질의함.
  - 그 결과 키 불일치(`unrecognized JWT kid for algorithm ES256`)가 발생하여 토큰 검증이 실패(401 Unauthorized)한 것임.
- **해결 조치**:
  1. `api/_lib/supabase.js`: 죽은 옛날 DB 주소(`ylhbaiolxexzkuinsprj`)가 환경변수에 들어있더라도 이를 원천 차단하고 신규 프로젝트 자격 증명만을 사용하도록 강력한 필터링 코드 탑재.
  2. Vercel CLI 명령어로 Vercel 클라우드의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 신규 Supabase 자격 증명으로 100% 덮어쓰기 완료.

### 문제 6. 브라우저 캐시 및 프론트엔드 에러 화면 갇힘 현상
- **증상**: 백엔드를 고쳤음에도 화면 새로고침 시 계속 `Unauthorized: Invalid token` 에러가 그대로 남아있음.
- **원인**:
  - 브라우저의 `localStorage`에 과거 로그인 시도 과정에서 발급받은 '만료되었거나 잘못된 토큰'이 영구 캐시되어 있었음.
  - 기존 `app.js`는 401(토큰 무효) 에러가 발생해도 세션을 비우거나 로그인 창으로 돌려보내지 않고, 단순히 빨간 에러 텍스트만 출력하고 멈춰버려 사용자가 에러 화면에 갇힘.
- **해결 조치**:
  1. `app.js`에 401 에러 감지 로직 추가: 백엔드로부터 401을 받으면 즉시 브라우저의 세션을 자동 초기화(`signOut()`)하고 로그인 폼으로 매끄럽게 복귀시킴.
  2. 혹시 모를 상황에 대비하여 에러 화면 중앙에 **[세션 초기화 후 다시 로그인]** 버튼을 추가 탑재.

---

### 문제 7. 로컬 개발 서버(`vercel dev`)의 500 에러
- **증상**: 배포 사이트에서는 200 OK가 나오는데 로컬 `http://localhost:3000`에서만 `500 FUNCTION_INVOCATION_FAILED` 에러 발생.
- **원인**:
  - 터미널에서 실행 중이던 `vercel dev` 프로세스가 `"type": "module"` 설정 이전에 켜져 있던 프로세스여서 이전 모듈 로더를 유지하고 있었음.
- **해결 조치**:
  - 로컬 터미널에서 `vercel dev`를 재시작(`Ctrl + C` 후 다시 실행)하면 새로운 환경 설정이 완벽히 반영됨.
