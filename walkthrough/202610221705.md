# 실시간 채팅 및 스토리지 복구 결과서 (Walkthrough)

- **작성일시**: 2026-10-22 17:05
- **작업명**: Supabase 신규 인스턴스 내 실시간 채팅 테이블 및 스토리지 환경 복구

---

## 1. 개요 및 원인 분석

- **현상**: 실시간 채팅창을 열어도 기존 메시지가 로드되지 않고, 메시지 전송 및 프로필/채팅 이미지 첨부 기능이 작동하지 않음.
- **원인**:
  1. 신규 Supabase DB(`qzbkalpmjjfzroenmoyi`) 생성 이후, 채팅 데이터가 저장될 `public.messages` 테이블이 미생성 상태였음 (`schema cache` 미등록 오류).
  2. Supabase 실시간 브로드캐스팅 채널인 `supabase_realtime` publication에 `messages` 테이블이 등록되어 있지 않아 웹소켓 이벤트가 발행되지 못함.
  3. Supabase Storage에 프로필 사진용 `avatars` 및 채팅 첨부용 `chat-images` 버킷이 생성되어 있지 않았음.

---

## 2. 조치 내역

### 1) `public.messages` 테이블 및 RLS 정책 생성
- 테이블 스키마 구성:
  - `id`: UUID (Primary Key, 기본값 `gen_random_uuid()`)
  - `content`: TEXT NOT NULL
  - `user_email`: TEXT NOT NULL
  - `avatar_url`: TEXT DEFAULT ''
  - `user_id`: UUID REFERENCES auth.users(id)
  - `created_at`: TIMESTAMPTZ DEFAULT now()
- RLS 정책 적용:
  - `SELECT`: 모든 사용자(`authenticated`, `anon`) 조회 허용
  - `INSERT`: 로그인한 사용자(`authenticated`) 추가 허용

### 2) Realtime Publication 활성화
- `ALTER PUBLICATION supabase_realtime ADD TABLE public.messages;` 실행 완료.

### 3) Storage 버킷 생성 및 RLS 정책 적용
- 버킷 생성:
  - `avatars` (Public 버킷, 이미지 MIME 타입 제한)
  - `chat-images` (Public 버킷, 이미지 MIME 타입 제한)
- `storage.objects` 보안 정책:
  - 누구나 파일 조회(다운로드) 허용
  - 로그인한 사용자만 파일 업로드 및 수정 허용
